## What shipped, in one paragraph each

**Epic `7oo` (closed).** Ten defects fixed and verified against the real
machine, both elevated and unelevated -- occluded wizard buttons, wrong Force
Uninstall entries, an over-broad system-component filter, no scan progress,
wrong redundancy grouping, no Windows Features toggle, a dead storage panel,
and startup items that were detection-only. The `7oo.10` real-data harness
(`test/real-data-verify.js`) is the reason any of this could be trusted --
it reproduced six of the ten defects before they were fixed, against a stub
suite that was reporting 312/312 green the whole time.

**Pre-release packaging (`3xo`).** `Vanish.cmd` double-click launcher,
`electron-builder` NSIS + portable targets. Found and fixed two blockers that
would have made any packaged build non-functional: `scanner.ps1` unreadable
from inside `app.asar` by `powershell.exe`, and `corrections.json` -- the
primary uninstaller-switch lookup -- accidentally deleted during a repo
cleanup pass, which took 27 test assertions offline as `NOT RUN` rather than
`FAILED`.

**Portable-exe elevation bug (`jhh`, fixed, not yet console-verified).**
`attemptElevatedRelaunch` used `process.execPath`, which for a portable build
is a temp-extracted copy the old instance can delete out from under the new
elevated one mid-relaunch -- a blank navy window with no content. Fixed by
preferring `PORTABLE_EXECUTABLE_FILE`, the stable path electron-builder sets
for exactly this case.

**Left-over Store app data sweep (`udu`, closed).** Seventh System Clean
cleaner. `%LOCALAPPDATA%\Packages` folders whose package is registered
nowhere -- union of current-user and, elevated, every user's registrations;
Windows' own families listed but never removable; folders touched in the last
7 days held back; folders that were never package folders at all (AppContainer
sandboxes like Chrome's `cr.sb.*`) excluded by shape. First file-kind cleaner
-- `cleaner-purge` gained a files branch. Found `Get-FolderSize` had always
returned 0 (`return if (...) {...}` is not valid PS 5.1) and fixed it.

**Startup items made actionable (`7oo.11`, closed).** Three narrow engine
verbs behind one IPC handler: remove a Run/RunOnce value, set a service to
Manual, disable/enable a scheduled task. Registry and service changes export a
manifest-only `.reg` to the vault before writing. Each verb refuses outside its
own surface (five Run keys only, no boot-start drivers, nothing under
`\Microsoft\`).

**Network attribution panel (`bfh.1`, closed).** A Health Advisor section that
reaches a verdict about the network -- including the negative one, "nothing
here is using it," which points the reader at their router instead of leaving
them clicking around the app. Zero network I/O (`INV-4` asserted by name in
`test/network-verify.ps1`, including `Test-NetConnection` and `Test-Connection`
individually). Never claims a per-process byte rate -- Windows cannot attribute
one without an ETW trace, and the harness fails any row that tries. Found and
fixed a `$host` automatic-variable bug that silently made every process report
exactly one peer.

**Network hold (`bfh.2`, shipped, elevated round trip not yet run).** Caps
Delivery Optimization's background bandwidth and suspends running BITS jobs.
Capture is written to disk *before* anything is changed, so a crash mid-hold
leaves either an untouched machine or a file describing exactly what to put
back; `releaseStaleNetworkHold()` reverts one automatically at the next
elevated start. A partial release keeps its record rather than dropping it.

**Commercialization ADR (`2c6`, closed).** `adrs/0002-...md`: personal use
free, commercial use paid, superseding only the payments row of ADR 0001.
Explicitly leaves price, per-seat-vs-site, licence enforcement, and the repo
licence text undecided. Signing hardens from optional to disqualifying-if-
absent; `1w0` needs splitting into signing (required) and channel (open).

**A second UI pass (five issues, closed 2026-08-07):** startup items covered

## Two lessons worth carrying forward, found twice each

- **`test/real-data-verify.js` passes ground truth (`truth`) only to sections
  named in one array inside `runSections`.** A new section that reads `truth`
  without being added to that array throws `truth is not defined` at runtime,
  not at review time. Hit by `sectionStartupItems` and `sectionNetwork` in the
  same week. The array now has a comment explaining why it exists -- check it
  before adding a section that needs machine ground truth.
- **This codebase has no CSS scoping.** A new class name is a global, and the
  uninstall wizard's `.mode-card` was silently reused by a new Settings block,
  breaking a screen nowhere near the change. `grep` any new class name against
  `index.css` before using it for something new.
